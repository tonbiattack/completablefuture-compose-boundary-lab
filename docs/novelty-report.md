# 題材重複調査記録

既存のQiita下書きとJava教材リポジトリを検索した。大分類としては近い下書きが存在するため、直接原因・実境界・観測契約・最小修正の四軸で差分を確認した。

| 軸 | 今回 | 既存題材との差分 |
|---|---|---|
| 直接原因 | thenApply相当の処理はCompletableFuture<CompletableFuture<String>>を作る。非同期処理の結果を一つのCompletableFuture<String>へ平坦化するにはthenComposeを使う。修正前はFutureオブジェクトを文字列化し、期待する大文字文字列を返さない。 | 既存下書きのjoinによるCompletionExceptionやリトライ判定ではなく、今回は値変換と非同期段階のflattening契約を扱う。
| 実境界 | Spring Boot Bean上の単一Java APIサービス | 既存記事とは異なる呼び出し・ライフサイクル境界 |
| 観測契約 | 例外の主従、Futureの型、Streamの評価回数 | 既存記事とは異なる最終観測 |
| 最小修正 | 元の例外・段階・終端契約を保持する | 既存記事と異なる修正中心 |

判定は「重複なし」。単なるクラス名・データの変更ではなく、失敗条件と修正契約を変更している。
